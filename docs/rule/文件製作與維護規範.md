# 文件製作與維護規範

本文件規範專案內所有文件的存放位置、撰寫方式與更新時機。人類與 AI Agent 都必須遵守。

## 1. 文件放哪裡

| 內容 | 位置 | 會進 GitLab |
|---|---|---|
| 專案簡介、安裝、啟動、測試 | `README.md` | 是 |
| 教學章節 | `docs/NN-<topic>.md` | 是 |
| 團隊規範（開發、Git、文件） | `docs/rule/` | 是 |
| AI Agent 守則入口 | `AGENT.md` or `CLAUDE.md` | 是 |
| Issue / MR 模板 | `.gitlab/issue_templates/`、`.gitlab/merge_request_templates/` | 是 |
| 設定範例（不含真實值） | `.env.example` | 是 |
| 個人開發筆記、草稿 | `docs/LOCAL/` | 否 |
| 待辦、需求、Bug、討論 | GitLab Issue | — |

- 不屬於上表的新文件類型，先在 MR 中說明理由，經 reviewer 同意後再新增位置。
- `docs/LOCAL/` 的內容不可被正式文件連結引用；需要分享時，整理成正式文件後再提交。

## 2. 單一文件單一功能

- 每一份文件都要視為一份說明手冊：讀者只看這一份，就能完成它所描述的事。
- 一份文件只處理一個主題；內容開始涵蓋第二個主題時，拆成兩份並互相連結。
- 同一件事只在一個地方寫（Single Source of Truth）；其他文件用連結引用，不複製貼上。
- 文件開頭第一段用一兩句話說明：這份文件的目的、給誰看。

## 3. 更新時機

- 每當 MR 開立前，都應當對於該分支內的改動範圍進行文件檢視。
- 程式變更與對應的文件更新放在**同一個 MR**，不另開「之後補文件」的 MR。
- 以下變更必須同步檢查文件：
  - 新增或修改功能、API、CLI 指令
  - 新增、刪除或改名環境變數（同步更新 `.env.example`）
  - 依賴、Python 版本、Docker 或啟動方式變更（同步更新 `README.md`）
  - CI/CD 流程或 job 變更
  - 團隊規範變更（同步更新 `docs/rule/` 與 `AGENT.md` 的引用）
- MR 模板中的「已更新相關文件」只有在實際檢視後才能勾選；確認不需更新時，在 MR 描述中註明「文件無需更新」。

## 4. TODO

- 所有 TODO 都應當開立 Issue 在 GitLab 中。
- 不應該以 TODO.md 或相關文件作為 TODO List 或是 TODO 文件。
- 程式碼中若需標記待處理位置，必須附上 Issue 編號，例如 `# TODO(#42): handle empty input`；沒有 Issue 編號的 TODO 不得合併。
- 文件中描述尚未完成的功能時，連結對應 Issue，不在文件內列待辦清單。

## 5. 撰寫格式

### 檔名

- 教學章節：`NN-<kebab-case>.md`，例如 `05-issues-and-templates.md`。
- 其他文件：英文、kebab-case 或 PascalCase 擇一，同一資料夾內保持一致。

### 結構

- 每份文件只有一個 `#` 一級標題，即文件名稱。
- 標題層級不跳級（`##` 之下才是 `###`）。
- 步驟用編號清單，規則用項目清單，對照資訊用表格。

### 內容

- 使用繁體中文；技術名詞、指令、檔名保留英文原文。
- 指令、路徑、設定值放在 code 標記或 code block 中，code block 標註語言（`bash`、`yaml`、`python`）。
- 文件中的指令必須實際執行過；無法驗證的步驟明確標示「未驗證」。
- 需依環境替換的值使用 `<placeholder>` 格式，例如 `<unit-group>`、`<project>`。
- 連結 repo 內文件一律使用相對路徑。
- 不寫入密碼、token、私鑰、真實 `.env` 內容或個人帳號；範例值使用明顯的假值。

## 6. 審查與淘汰

- 文件變更與程式碼相同，一律走分支與 MR，commit type 使用 `docs`，例如 `docs(readme): clarify setup steps`。
- Reviewer 檢查重點：內容是否正確、連結是否有效、指令是否可執行、是否與既有文件重複。
- 過時文件直接刪除或改寫，不保留「已棄用」的舊段落；歷史版本由 Git 追蹤。
- 刪除或改名文件時，同步更新所有指向它的連結。

## 7. 文件檢查清單（開 MR 前）

- [ ] 改動範圍涉及的文件都已檢視並更新
- [ ] 沒有新增 TODO.md 或無 Issue 編號的 TODO
- [ ] 沒有複製其他文件的內容，改以連結引用
- [ ] 文件中的指令已實際執行過
- [ ] 相對路徑連結皆有效
- [ ] 沒有敏感資訊
