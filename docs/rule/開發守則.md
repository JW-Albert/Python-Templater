# 開發守則

## 嚴格遵守以下守則進行開發

- Make it work 正確的動起來
- YAGNI 你真的不會再需要它
- KISS 樸實的簡單勝過華麗的複雜
- DRY 不要重複
- Clean Code 簡潔的程式碼
    - 有意義的命名：變數、函式與類別名稱應清楚表達用途，避免使用含糊代號或拼音縮寫。
    - 函式簡潔單一：函式應只做一件事（Single Responsibility），行數要短，參數越少越好。
    - 謹慎使用註解：好的程式碼本身就是最好的說明；註解應用來解釋「為什麼這麼做」，而不是重複「程式碼在做什麼」。
    - 保持良好排版與縮排：維持一致的程式碼風格，讓閱讀邏輯像在讀文章一樣順暢。
- Standing On The Shoulder of Giants 不要重複造輪
- Boy Scout Rule 離開時，比抵達時更美好
- Make It Fast 提高效能
- 遵守物件導向 GoF 與 SOLID 原則
- 重視單元測試
- 確保 高併發、低耦合。


## 針對 Python 程式碼(補充規則):

- 遵守 PEP8 規範，確保能通過 Ruff 測試。
- 使用 PyTest 進行單元測試。


## 良好註解的撰寫原則

- 說明「為什麼」，而不是「是什麼」：好的註解應該解釋程式碼背後的意圖或邏輯，而不是重複程式碼本身已經表達的內容。
- 保持簡短明瞭：避免冗長或過度複雜的技術術語。
- 風格一致：如果是完整的語句，注意大小寫與句號。
- 不要為爛代碼寫註解：若程式碼寫得很糟，應該先重構與重寫，而不是用註解去掩蓋。
- 刪除無用代碼：避免在檔案中留下大量被註解掉（Commented-out）的廢棄程式碼，應用版本控制工具（如 Git）來追蹤歷史。
